# Module 5: Event Correlation Engine

## Overview
The Event Correlation Engine correlates multiple related `SecuritySignal`s (generated by Module 4) into higher-confidence security `Incident`s. It supports correlation across multiple dimensions, including Time, Source IP, Destination IP, User Account, and specific attack chains.

## Architecture
The engine is modular and explainable:
- **CorrelationEngine**: The core that runs new signals against rules.
- **CorrelationContext**: Queries the database for recent signals to identify patterns.
- **IncidentScorer**: Deterministically calculates Confidence and Severity.
- **IncidentDeduplicator**: Merges new evidence into existing OPEN/NEW incidents to prevent spam.

## Rules Implemented
- `CORR-001`: Brute Force Leading to Success (T1110 -> T1078)
- `CORR-002`: Password Spraying Campaign (T1110.003)
- `CORR-003`: Port Scan Follow-up Activity (T1046)
- `CORR-004`: Suspicious Login to Process Execution (T1078 -> T1059)
- `CORR-005`: Process Execution to Outbound Connection (T1059 -> T1043)
- `CORR-006`: Multi-Source Correlation (Independent detections on the same entity)

## Integration
The engine is triggered synchronously from the `DetectionService` whenever a new `SecuritySignal` is generated. It maintains explainability by recording the precise reasons for correlation inside the `Incident.evidence`.

## APIs
- `GET /api/v1/correlation/rules`: List all correlation rules
- `POST /api/v1/correlation/rules/{rule_id}/enable`: Enable rule
- `POST /api/v1/correlation/rules/{rule_id}/disable`: Disable rule
- `GET /api/v1/incidents`: List incidents
- `GET /api/v1/incidents/{incident_id}`: Get incident
- `GET /api/v1/incidents/{incident_id}/timeline`: Get incident timeline
